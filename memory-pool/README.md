# 静态内存池（零 malloc）

用预分配的静态内存替代 `malloc/free`，解决嵌入式里"碎片 + 不确定时延"两个问题。

## 背景

采集系统里消息块频繁申请/释放。`malloc` 有两个致命问题：

1. **碎片**：长时间运行后，空闲内存总量够，但找不到连续块；
2. **不确定时延**：分配耗时取决于堆状态，不适合实时任务。

## 设计

| 池 | 结构 | 分配策略 | 适用 |
| --- | --- | --- | --- |
| 固定块池 | 8 块 × 64 B + 位图 | 找第一个空闲位，O(1) | 消息队列、固定大小帧 |
| 变长池 | 1024 B 连续区 + 块头链表 | 首次适配 + 相邻空闲块合并 | 不定长数据 |

接口：

```c
void  fixed_pool_init(fixed_pool_t *p);
void *fixed_pool_alloc(fixed_pool_t *p);
void  fixed_pool_free(fixed_pool_t *p, void *ptr);

void *var_pool_alloc(size_t size);
void  var_pool_free(void *ptr);
void  var_pool_status(void);      /* 打印空闲总量、碎片数、最大连续空闲、碎片率 */
```

## 关键指标：碎片率

`var_pool_status()` 不只打印"空闲总量"，还打印**最大连续空闲**：

```
释放 200B 后：
  空闲总计: 768B, 碎片数: 2, 最大连续空闲: 568B, 碎片率: 26%
```

含义：**总量 768 B 看着够，但 600 B 的请求会失败**——因为最大连续只有 568 B。
这比"碎片会降低利用率"这种定性描述有用得多。

全部释放后，相邻空闲块合并回 1000 B，碎片率归零。


## 实测结果

```
--- 固定块内存池 (8块 × 64B) ---
分配 3 个块: ... 
固定池: 3/8 块已用, alloc=3, free=0
释放块2: 固定池: 2/8 块已用

--- 可变块内存池 (1024B) ---
空闲总计: 1000B, 碎片数: 1, 最大连续空闲: 1000B, 碎片率: 0%
分配 v1(100B), v2(200B), v3(50B)

释放 v2 → 空闲总计: 768B, 碎片数: 2, 最大连续空闲: 568B, 碎片率: 26%
```

## 已知限制

- 当前实现**不是线程安全的**，RTOS 下需要关中断或互斥量保护；
- 变长池的块头有额外开销（`sizeof(mem_block_t)`），小块分配时开销占比高；
- 没有 all-allocators 的统计接口，只有单池状态打印。
